## Story
**As a** platform developer,
**I want** to set up the complete Supabase database schema with all required tables, policies, and functions,
**so that** the Moon Ring platform has a secure, scalable foundation for user management, subscriptions, health goals, and marketing data.

## Acceptance Criteria
1. [ ] Database schema includes all required tables: profiles, subscriptions, health_goals, goal_progress, leads
2. [ ] Row Level Security (RLS) policies are properly configured for all tables
3. [ ] Database functions and triggers are implemented for user creation workflow
4. [ ] Real-time subscriptions are enabled for relevant tables
5. [ ] Schema supports Stripe integration with proper subscription status tracking
6. [ ] Health category constraints match Moon Ring design system (movement, sleep, stress, recovery)
7. [ ] Migration files are properly structured and can be applied via Supabase CLI
8. [ ] All foreign key relationships are correctly defined with cascade deletion
9. [ ] Indexes are created for performance optimization on frequently queried columns
10. [ ] Database complies with HIPAA requirements for health data storage

## Dev Notes

### Database Architecture Context
**Source:** [implementation-guide-nextjs-supabase-stripe.md]

The database schema implements a comprehensive foundation for the Moon Ring platform supporting:
- **Multi-tenant Architecture**: RLS policies ensure user data isolation
- **Stripe Integration**: Full subscription lifecycle tracking with webhook support
- **Health Goal System**: Support for 4 health categories with progress tracking
- **Marketing Analytics**: Lead capture with UTM attribution tracking
- **Real-time Capabilities**: WebSocket support for live updates on goals and progress

### Schema Design Principles
**Source:** [implementation-guide-nextjs-supabase-stripe.md]

1. **Security First**: All user tables have RLS enabled with proper policies
2. **Audit Trail**: created_at and updated_at timestamps on all tables
3. **Data Integrity**: Foreign key constraints with appropriate cascade rules
4. **Performance**: Strategic indexing for common query patterns
5. **Extensibility**: UUID primary keys and flexible JSON fields where needed

### Key Technical Constraints
**Source:** [implementation-guide-nextjs-supabase-stripe.md]

- **Profile Creation**: Automatic via trigger on auth.users insertion
- **Subscription Status**: Must match Stripe webhook status values exactly
- **Health Categories**: Limited to: movement, sleep, stress, recovery (matching design system)
- **Lead Status**: Tracks conversion funnel: new, contacted, qualified, converted
- **Timezone Handling**: All timestamps use 'UTC' timezone for consistency

### Row Level Security Implementation
**Source:** [implementation-guide-nextjs-supabase-stripe.md]

- **User Data Access**: auth.uid() = user_id pattern for all user tables
- **Admin Access**: service_role access for leads table only
- **Cross-table Permissions**: Consistent user_id checking across related tables
- **Real-time Security**: RLS policies apply to real-time subscriptions

### Performance Considerations
**Source:** [implementation-guide-nextjs-supabase-stripe.md]

- **Query Optimization**: Indexes on user_id, created_at, and Stripe ID fields
- **Real-time Efficiency**: Limited real-time publications to essential tables
- **Connection Pooling**: Supabase handles connection management automatically
- **Data Types**: Appropriate use of UUID, TEXT, NUMERIC, and TIMESTAMP types

### Testing Requirements
**Source:** [implementation-guide-nextjs-supabase-stripe.md]

- **Migration Testing**: Verify all migrations apply cleanly on fresh database
- **RLS Testing**: Confirm policies prevent unauthorized data access
- **Function Testing**: Validate trigger functions create profiles correctly
- **Constraint Testing**: Verify enum constraints and foreign key relationships
- **Performance Testing**: Check query performance with indexed columns
