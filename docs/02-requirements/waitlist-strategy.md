## 🎯 Executive Summary

This waitlist strategy applies Moon Ring's core value proposition—behavioral psychology and social accountability—to the pre-launch phase itself. Rather than passive email collection, we create a **self-selecting, highly-engaged audience** that's already practicing commitment behaviors before launch.

**Core Principle:** *Your waitlist isn't just lead generation—it's pre-commitment training.*

**Expected Outcomes (8-week pre-launch):**
- 10,000+ waitlist signups
- 50% waitlist → trial conversion (vs 15% industry avg)
- 35% trial → paid conversion (vs 25% industry avg)
- $26K+ MRR from founding members
- Top-of-mind brand awareness in wearable accountability space

## Phase 1: High-Converting Waitlist Capture

### 1.1 Multi-Tier Waitlist Strategy

#### Tier 1: Curiosity Seekers (Low commitment, high volume)
**Landing Page CTA:** "Join 10,000+ people getting early access"
**Ask:** Email only
**Incentive:** "Be first to know when we launch"
**Conversion Target:** 8-12% of landing page visitors

#### Tier 2: Engaged Learners (Medium commitment, qualified)
**Offer:** Presented after Tier 1 signup
**CTA:** "Want exclusive behavioral change insights?"
**Ask:** Email + Name + Primary health goal (Movement/Sleep/Stress/Recovery)
**Incentive:** "Free 30-Day Behavioral Change Starter Kit" (PDF)
**Conversion Target:** 40% of Tier 1 → Tier 2

#### Tier 3: Founding Members (High commitment, champions)
**Offer:** Presented in Email #3 of nurture sequence
**CTA:** "Become a Founding Member"
**Ask:**
- Detailed preferences survey
- Refer 3 friends minimum
- Pre-commitment to trial on launch
**Incentive:**
- 50% lifetime discount (or pay-what-you-want pricing)
- Direct influence on product roadmap
- Exclusive founder badge in app
**Conversion Target:** 15% of Tier 2 → Tier 3

**Behavioral Psychology Principles Applied:**
- **Foot-in-the-door technique:** Start with tiny ask (email), build to larger commitments
- **Progressive commitment:** Each tier increases investment, strengthening commitment
- **Self-selection:** High-intent users naturally progress to Tier 3

```typescript
import { createServerActionClient } from '@/lib/supabase/server'
import { sendEmail, waitlistSequences } from '@/lib/email/brevo'

export default async function handler(req: Request) {
  // Verify cron secret
  if (req.headers.get('authorization') !== `Bearer ${process.env.CRON_SECRET}`) {
    return new Response('Unauthorized', { status: 401 })
  }

  const supabase = await createServerActionClient()
  const now = new Date()

  // Week 1: Welcome email (send 1 hour after signup)
  const week1Users = await supabase
    .from('email_subscriptions')
    .select('*')
    .eq('waitlist_tier', 'tier1')
    .gte('created_at', new Date(now.getTime() - 2 * 60 * 60 * 1000).toISOString()) // Last 2 hours
    .lte('created_at', new Date(now.getTime() - 1 * 60 * 60 * 1000).toISOString()) // At least 1 hour ago
    .is('tier2_upgraded_at', null) // Haven't upgraded yet

  for (const user of week1Users.data || []) {
    const template = waitlistSequences.week1Welcome(
      user.email,
      user.name,
      user.waitlist_position
    )
    await sendEmail({
      to: user.email,
      ...template
    })
  }

  // Week 2: Identity priming (7 days after signup)
  const week2Users = await supabase
    .from('email_subscriptions')
    .select('*')
    .gte('created_at', new Date(now.getTime() - 7 * 24 * 60 * 60 * 1000 - 60 * 60 * 1000).toISOString())
    .lte('created_at', new Date(now.getTime() - 7 * 24 * 60 * 60 * 1000).toISOString())
    .not('primary_health_goal', 'is', null) // Has selected goal

  for (const user of week2Users.data || []) {
    const template = waitlistSequences.week2Identity(
      user.email,
      user.name,
      user.primary_health_goal
    )
    await sendEmail({
      to: user.email,
      ...template
    })
  }

  // Continue for weeks 3-8...

  return new Response('Emails sent', { status: 200 })
}
```

#### Process Referral Rewards:
```typescript
// lib/waitlist/referrals.ts
async function processReferral(
  referrerCode: string,
  referredEmail: string,
  referredName: string
) {
  const supabase = await createServerActionClient()

  // Find referrer
  const { data: referrer } = await supabase
    .from('email_subscriptions')
    .select('*')
    .eq('referral_code', referrerCode)
    .single()

  if (!referrer) return

  // Create referral record
  await supabase.from('referrals').insert({
    referrer_email: referrer.email,
    referrer_code: referrerCode,
    referred_email: referredEmail,
    referred_name: referredName,
    status: 'completed',
    completed_at: new Date().toISOString(),
  })

  // Update referrer stats
  const newReferralCount = referrer.referral_count + 1
  const newPosition = Math.max(1, referrer.waitlist_position - 500)

  // Check for badge unlocks
  const badges = referrer.badges || []
  if (newReferralCount === 1 && !badges.includes('bronze_referrer')) {
    badges.push('bronze_referrer')
  }
  if (newReferralCount === 3 && !badges.includes('silver_referrer')) {
    badges.push('silver_referrer')
  }
  if (newReferralCount >= 5 && !badges.includes('gold_referrer')) {
    badges.push('gold_referrer')
    // Auto-upgrade to Tier 3 (Founding Member)
    await supabase
      .from('email_subscriptions')
      .update({
        waitlist_tier: 'tier3',
        tier3_upgraded_at: new Date().toISOString(),
        founding_member: true,
      })
      .eq('email', referrer.email)
  }
```

### 5.5 Leaderboard & Position Updates

#### Real-time Position Updates:
```typescript
// pages/api/cron/update-positions.ts (runs every 30 min)
export default async function handler(req: Request) {
  const supabase = await createServerActionClient()

  // Recalculate positions based on:
  // 1. Signup date (earlier = higher)
  // 2. Referral count (more = higher)
  // 3. Engagement score (higher = higher)

  const { data: users } = await supabase
    .from('email_subscriptions')
    .select('*')
    .order('created_at', { ascending: true })

  // Calculate weighted position
  const usersWithScore = users.map((user, index) => ({
    email: user.email,
    basePosition: index + 1,
    referralBonus: user.referral_count * 500,
    engagementBonus: user.engagement_score * 10,
    finalPosition: Math.max(1, (index + 1) - (user.referral_count * 500) - (user.engagement_score * 10))
  }))

  // Sort by final position
  usersWithScore.sort((a, b) => a.finalPosition - b.finalPosition)

  // Update positions in DB
  for (let i = 0; i < usersWithScore.length; i++) {
    await supabase
      .from('email_subscriptions')
      .update({ waitlist_position: i + 1 })
      .eq('email', usersWithScore[i].email)
  }

  return new Response('Positions updated', { status: 200 })
}
```

## Risk Mitigation

### Potential Issues & Solutions

#### Issue 1: Low Referral Participation (<20%)
**Solution:**
- A/B test referral incentives (position vs feature unlock vs discount)
- Simplify sharing (1-click social share buttons)
- Increase urgency ("Only 48 hours to unlock Founding Member via referral")

#### Issue 2: Email Fatigue (High Unsubscribe Rate >5%)
**Solution:**
- Reduce cadence from 2x/week to 1x/week
- Segment more aggressively (only send relevant content)
- Add email preference center ("Choose your topics")

#### Issue 3: Low Tier 1 → Tier 2 Conversion (<30%)
**Solution:**
- Improve lead magnet value (better PDF, video course instead)
- Earlier ask (goal selection on landing page, not Week 1 email)
- Stronger FOMO ("Tier 2 members get first access to beta")

#### Issue 4: Founding Member Offer Underperforms (<10% take-rate)
**Solution:**
- Increase scarcity ("Only 100 spots left" with real countdown)
- Better value stack (add more perks: merch, 1:1 onboarding, etc.)
- Payment flexibility (allow $5 deposit to lock in, pay later)

#### Issue 5: Launch Day Technical Issues (Server crash, auth bugs)
**Solution:**
- Load test pre-launch (simulate 5,000 concurrent logins)
- Gradual rollout (activate in batches: Tier 3 first, then Tier 2, then Tier 1)
- Clear communication (status page, support ready, founder updates)
